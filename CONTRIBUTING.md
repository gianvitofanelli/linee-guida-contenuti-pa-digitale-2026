# Come contribuire

## Prima di modificare

- Segui le regole delle stesse linee guida: capitolo 3 (linguaggio chiaro), capitolo 5 (convenzioni) e capitolo 11 (checklist).
- Una modifica a una regola va motivata. Se cambia una regola già in uso, aggiorna anche gli esempi Sì / No.
- I contenuti con valore giuridico (capitolo 9) non si cambiano senza verifica giuridica.

## Pull request

1. Modifica i file in `content/`. Non modificare `_site/`: si genera da solo.
2. Descrivi nella pull request cosa cambia e perché. Per le correzioni a un testo altrui usa una tabella con tre colonne: problema, correzione, motivo.
3. Se la modifica cambia il significato di una regola, aggiungi una riga a `CHANGELOG.md`.
4. Una persona diversa da chi ha scritto controlla il testo prima dell'approvazione.

## Proposte senza testo

Apri una issue con il modulo "Proposta di modifica": regola attuale, problema, proposta, esempio. Le proposte si raccolgono tutte nelle issue.

## Revisione periodica

Revisione ordinaria ogni sei mesi. Revisione straordinaria quando cambia il design system .italia, cambia una denominazione ufficiale o esce un avviso con nuovi tipi di contenuto.
